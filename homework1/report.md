## 解題說明

本題要求實作阿克曼函數（Ackermann's function），計算 $A(m, n)$ 之值。為了深入探討演算法機制，本作業分別採用**遞迴（Recursive）**與**非遞迴（Non-recursive）**兩種方式進行實作與比較。

### 解題策略

1. **遞迴版本：**
   - 直接將數學定義轉化為條件判斷式。
   - 透過系統隱式呼叫堆疊（Implicit Call Stack）自動處理雙重遞迴 $A(m - 1, A(m, n - 1))$ 的運算順序。
2. **非遞迴版本：**
   - 使用一維陣列 `nfu` 與指標 `top` 自訂顯式堆疊（Explicit Stack）模擬遞迴過程。
   - 透過 `while (top >= 0)` 迴圈處理狀態轉移：
     - 當 $cur\_m = 0$ 時：代表達到基底條件，將 $n$ 加 1（`n = n + 1`）。
     - 當 $n = 0$ 時：對應 $A(m-1, 1)$，更新堆疊頂端為 $cur\_m - 1$，並設 $n = 1$。
     - 其餘情況：對應 $A(m-1, A(m, n-1))$，依序將外層任務 $cur\_m - 1$ 與內層任務 $cur\_m$ 推入堆疊，並將 $n$ 減 1（`n = n - 1`）。

## 程式實作

以下為包含「遞迴」與「非遞迴」兩版本的完整 C++ 程式碼：

**遞迴版本：**
```cpp
#include <iostream>
using namespace std;
int nfu(int m, int n) {
if (m == 0) {
return n + 1;
}
if (n == 0) {
return nfu(m - 1, 1);
}
return nfu(m - 1, nfu(m, n - 1));
}

int main() {
int m, n;
cout << "輸入 m 和 n: ";
cin >> m >> n;
cout << "結果: " << nfu(m, n) << endl
return 0;
}
```
**非遞迴版本：**
```cpp
#include <iostream>
using namespace std;
int data(int m, int n) {
    int nfu[100000]; 
    int top = -1; 
    top++;
    nfu[top] = m;
    while (top >= 0) {
    int cur_m = nfu[top];
        top--;
        if (cur_m == 0) {
            n = n + 1;
        } 
        else if (n == 0) {
            top++;
            nfu[top] = cur_m - 1; 
            n = 1;
        } 
        else {
            top++;
            nfu[top] = cur_m - 1;
            top++;
            nfu[top] = cur_m;  
            n = n - 1;
        }
    }
    return n;
}
int main() {
    int m, n;
    cout << "請輸入 m 和 n: ";
    cin >> m >> n;
    cout << "計算結果 (非遞迴): " << data(m, n) << endl;
    return 0;
}
```

## 申論及開發報告

### 阿克曼函數：遞迴 vs 非遞迴實作差異探討

為了比較兩種寫法的實作差異，我同時開發了遞迴與非遞迴版本。

#### 1. 記憶體管理：系統 Call Stack vs 自訂 Stack

- **遞迴寫法（用系統的 Call Stack）：**  
  如果用一般的遞迴寫，程式每呼叫自己一次，系統就會在 Call Stack 裡面開一塊空間（Stack Frame）來記住現在跑到哪、變數是多少。但系統給的 Call Stack 空間非常小，如果數字稍微大一點點，系統堆疊就直接被塞爆，跳出慘絕人寰的 **Stack Overflow** 崩潰。

- **非遞迴寫法（我們自己建的 Stack）：**  
  為了避免系統 Stack 溢位，我們改成用非遞迴，並自己宣告一個陣列 `nfu` 當做 Stack。自己建的 Stack 是放在主記憶體的資料區（Data Segment），空間比系統 Call Stack 大太多了！這樣就部會受限於數字大小

#### 2. 控制流程：自動配對 vs 手動排隊

- **遞迴寫法：**  
  碰到像 $A(m - 1, A(m, n - 1))$ 這種兩層遞迴時，編譯器跟系統會自動幫你處理好「先算內層、再算外層」的順序。程式碼看起來非常乾淨優雅，跟數學公式長得一模一樣，但底層到底是怎麼轉的你其實看不到。

- **非遞迴寫法：**  
  沒有系統幫忙，我們就必須自己來。程式裡把 $m - 1$ 跟 $m$ 依序推進 Stack 裡面，其實就是我們手動在指揮：「先拿內層的 $A(m, n-1)$ 出來算，算完結果再丟給外層的 $m-1$」。雖然寫起來比較複雜，但可以掌握整個運算過程。

#### 3. 區別

| 比較項目 | 遞迴版本 (Recursive) | 非遞迴版本 (Non-recursive) |
|:---|:---|:---|
| **程式碼可讀性** | 比較直觀（跟數學公式一樣直觀） | 比較複雜（要手動管理 Stack 跟 while 迴圈） |
| **記憶體用哪裡** | 空間超小的系統 Call Stack | 空間大很多的自訂陣列 (Data Segment) |
| **執行效率** | 頻繁進出函式，額外開銷（Function Call Overhead）較大 | 無函式呼叫開銷，狀態轉移比較快 |
| **當機 (Overflow) 風險** | 輸入超小（如 $m=3, n=4$）就會直接崩潰 | 空間承受力高很多，但受限於陣列 `nfu[100000]` 的大小 |

#### 4. 總結

雖然阿克曼函數用遞迴寫最直覺，但因為系統記憶體的瓶頸，在實際應用上非遞迴版本具有更好的抗溢位能力。透過同時實作這兩種方案，驗證了結果的精確性，也讓我更清楚看到程式底層在處理複雜邏輯時，記憶體與堆疊到底是怎麼運作的。

## 解題說明

本作業旨在利用**遞迴（Recursion）**與**二元決策樹（Binary Decision Tree）**的概念，實作並探討如何列印出一個給定集合 $S$ 的所有子集合（即該集合的「冪集」 Power Set）。

### 冪集（Power Set）定義

若集合 $S$ 包含 $n$ 個元素，則 $S$ 的冪集 $\mathcal{P}(S)$ 為包含 $S$ 所有可能子集合（包含空集合與自身）的集合：

$$
|\mathcal{P}(S)| = 2^n
$$

對於集合中的每一個元素 $S[i]$，在建構子集合時都只有兩種選擇：
1. **不納入（Exclude）：** 不將該元素加入當前子集合。
2. **納入（Include）：** 將該元素加入當前子集合。
## 程式實作

以下為列印集合所有子集合之完整 C++ 程式碼：

```cpp
#include <iostream>
#include <string>
using namespace std;
void nfu(string S, int n, int index, string current) {
    if (index == n) {
        cout << "(" << current << ")" << endl;
        return;
    }
    
    nfu(S, n, index + 1, current);
    nfu(S, n, index + 1, current + S[index]);
}

int main() {
    int n;
    cout << "請輸入集合有幾個元素 (n): ";
    cin >> n;
    
    string S = "";
    cout << "請輸入 " << n << " 個字元 : ";
    for (int i = 0; i < n; i++) {
        char ch;
        cin >> ch;
        S += ch;
    }
    
    cout << "nfu(S) 的所有子集合結果：" << endl;
    nfu(S, n, 0, "");
    
    return 0;
}
```
## 效能分析

### 時間複雜度

- **總節點數 / 呼叫次數：** 決策樹的深度為 $n$，形成的滿二元樹（Full Binary Tree）總葉子節點數為 $2^n$ 個（對應 $2^n$ 個子集合），總呼叫節點數為 $2^{n+1} - 1$。
- **字串複製開銷：** 在最深層印出子集合時，平均字串長度為 $\frac{n}{2}$，印出總代價為 $O(n \cdot 2^n)$。
- **總時間複雜度：** **$O(n \cdot 2^n)$**。

### 空間複雜度

- **呼叫堆疊（Call Stack）深度：** 遞迴調用最深到達第 $n$ 層，故 Call Stack 的最大深度為 $O(n)$。
- **字串空間：** 每次遞迴傳值時傳遞字串副本，累積空間開銷為 $O(n^2)$（若考慮字串長度）；若以記憶體堆疊上限來看，主要受限於 $O(n)$ 的遞迴深度。
- **總空間複雜度：** **$O(n)$**（輔助空間）。

### 子集合生成演算法：遞迴決策樹與狀態空間探索

本作業實作的 `nfu` 函式是求解組合問題（Combinatorial Problems）中非常經典的**回溯與遞迴探索（Backtracking & Recursive Exploration）**範例。

#### 1. 遞迴決策樹（Binary Decision Tree）的運算機制

在生成子集合的過程中，演算法本質上是在建立一棵**高度為 $n$ 的二元決策樹**：
- **樹的每一層（Depth $i$）：** 代表對第 $i$ 個元素 `S[i]` 做抉擇。
- **左分支（Left Branch）：** 走 `nfu(S, n, index + 1, current)`，代表**不安插**該字元。
- **右分支（Right Branch）：** 走 `nfu(S, n, index + 1, current + S[index])`，代表**安插**該字元。

因為每個節點都有 2 個分支，走到底部（`index == n`）時共有 **$2^n$** 個葉子節點，正好對應了冪集中的所有可能元素。

#### 2. 傳值（Pass-by-Value）與自動狀態復原

在程式碼中，`current` 參數是以**傳值（Pass-by-Value）**方式進行傳遞：
- 當呼叫 `current + S[index]` 時，會產生一個全新的字串給下一層函式使用。
- 當右分支的遞迴執行完畢退回上一層時，當前層級的 `current` 變數**完全不受影響**。
- 這帶來了寫法簡單、無需手動進行「Pop/移除字元（Backtrack）」的好處；但也因為每次呼叫都複製字串，產生了額外的記憶體開銷。

#### 3. 效能瓶頸與優化方向

- **記憶體優化（引用傳遞 + 回溯）：**  
  若欲進一步優化記憶體，可以改用 `string& current`（引用傳遞），並在遞迴呼叫後手動執行 `current.pop_back()` 進行復原。這樣全域只需要維持一份字串空間，空間開銷能純粹優化至 $O(n)$。
- **位元遮罩實作（Bitmask Approach）：**  
  除了遞迴寫法外，由於每個元素的「選與不選」正好能對應到二進位的 `0` 與 `1`，因此也可以利用迴圈從 $0$ 跑至 $2^n - 1$，透過二進位位元檢查（Bitwise AND）來生成對應子集合，能完全避免遞迴呼叫的開銷。

#### 4. 總結

透過這次的實作，我們不僅學會了如何使用遞迴列舉出集合的所有子集合，更深入理解了**二元決策樹**在演算法中的應用。這種「選/不選」的遞迴決策模型，也是後續學習動態規劃（如 0/1 背包問題）與回溯法極為重要的基本功。
