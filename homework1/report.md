## 解題說明

本題要求實作非遞迴（迭代）版本的阿克曼函數（Ackermann's function），計算 $A(m, n)$ 之值。

### 阿克曼函數數學定義

阿克曼函數定義如下：

$$A(m, n) =  \begin{cases}  n + 1 & \text{if } m = 0 \\  A(m - 1, 1) & \text{if } n = 0 \\  A(m - 1, A(m, n - 1)) & \text{otherwise}  \end{cases}$$

### 解題策略

1. 由於阿克曼函數成長速度極快，遞迴呼叫容易造成系統呼叫堆疊（Call Stack）溢位，本實作採用**自訂堆疊（陣列 `nfu`）**模擬遞迴過程：
   - 使用一維陣列 `nfu` 與指標 `top` 來管理堆疊狀態。
   - 初始時將參數 $m$ 推入堆疊中。
2. 透過 `while (top >= 0)` 迴圈模擬遞迴呼叫與返回流程：
   - 當 $cur\_m = 0$ 時：代表達到基底條件，將 $n$ 加 1（`n = n + 1`）。
   - 當 $n = 0$ 時：對應 $A(m-1, 1)$，更新堆疊頂端為 $cur\_m - 1$，並設 $n = 1$。
   - 其餘情況：對應 $A(m-1, A(m, n-1))$，依序將外層任務 $cur\_m - 1$ 與內層任務 $cur\_m$ 推入堆疊，並將 $n$ 減 1（`n = n - 1`）。
3. 當堆疊清空（`top < 0`）時結束迴圈，主程式呼叫函式並輸出計算結果。

## 程式實作

以下為主要程式碼：

```cpp
#include <iostream>
using namespace std;

int data(int m, int n) {
    int nfu[100000]; 
    int top = -1; 
    top++;
    nfu[top] = m;
    while (top >= 0) {
        int cur_m = nfu[top];
        top--;
        if (cur_m == 0) {
            n = n + 1;
        } 
        else if (n == 0) {
            top++;
            nfu[top] = cur_m - 1; 
            n = 1;
        } 
        else {
            top++;
            nfu[top] = cur_m - 1;
            top++;
            nfu[top] = cur_m;  
            n = n - 1;
        }
    }
    return n;
}

int main() {
    int m, n;
    cout << "請輸入 m 和 n: ";
    cin >> m >> n;
    cout << "計算結果 (非遞迴): " << data(m, n) << endl;
    return 0;
}
```


## 效能分析

1. **時間複雜度：** 阿克曼函數為超越指數等級極速成長的函數。對於較小的 $m$ 值：
   - $m = 0: O(1)$
   - $m = 1: O(n)$
   - $m = 2: O(n)$
   - $m = 3: O(2^n)$
   - 一般性表達式為 $O(A(m, n))$，屬於極度爆炸性成長。
2. **空間複雜度：** $O(\text{Max Stack Depth})$。空間開銷取決於執行過程中自訂堆疊 `nfu` 的最大深度，最大開銷與當次運算所需的堆疊深度成正比。

## 申論及開發報告

### 選擇非遞迴（自訂 Stack）的原因

在本程式中，使用非遞迴配合自訂 Stack 計算阿克曼函數的主要原因如下：

1. **避免系統呼叫堆疊溢位（Stack Overflow）**  
   阿克曼函數的遞迴深度成長極快，若使用標準遞迴，系統指派給單一執行緒的有限 Call Stack 會在輸入稍大時瞬間溢位崩潰。改為非遞迴並在 Data Segment / Heap 自訂 Stack 陣列，能大幅提升程式可承受的運算深度。

2. **精確掌控子任務執行順序**  
   阿克曼函數包含複雜的雙重遞迴 $A(m-1, A(m, n-1))$。透過 Explicit Stack（顯式堆疊），能夠精確手動控制「先解內層子問題 $A(m, n-1)$，再將結果填回外層 $m-1$」的執行順序。

3. **實作優勢與限制**  
   - **優勢：** 邏輯完全不依賴系統遞迴機制，減少了頻繁函式呼叫（Function Call Overhead）的額外開銷。
   - **限制：** 由於函數本身理論成長率極高，若未搭配動態記憶體擴充機制與大數運算（Big Integer），固定大小的陣列依然有其極限。

透過非遞迴實作阿克曼函數，展現了利用資料結構（Stack）拆解複雜遞迴結構的核心思想。
