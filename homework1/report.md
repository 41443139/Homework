## 解題說明

本題要求實作非遞迴（迭代）版本的阿克曼函數（Ackermann's function），計算 $A(m, n)$ 之值。

### 阿克曼函數數學定義

阿克曼函數定義如下：

$$A(m, n) =  \begin{cases}  n + 1 & \text{if } m = 0 \\  A(m - 1, 1) & \text{if } n = 0 \\  A(m - 1, A(m, n - 1)) & \text{otherwise}  \end{cases}$$

### 解題策略

1. 由於阿克曼函數成長速度極快，遞迴呼叫容易造成系統呼叫堆疊（Call Stack）溢位，本實作採用**自訂堆疊（陣列 `nfu`）**模擬遞迴過程：
   - 使用一維陣列 `nfu` 與指標 `top` 來管理堆疊狀態。
   - 初始時將參數 $m$ 推入堆疊中。
2. 透過 `while (top >= 0)` 迴圈模擬遞迴呼叫與返回流程：
   - 當 $cur\_m = 0$ 時：代表達到基底條件，將 $n$ 加 1（`n = n + 1`）。
   - 當 $n = 0$ 時：對應 $A(m-1, 1)$，更新堆疊頂端為 $cur\_m - 1$，並設 $n = 1$。
   - 其餘情況：對應 $A(m-1, A(m, n-1))$，依序將外層任務 $cur\_m - 1$ 與內層任務 $cur\_m$ 推入堆疊，並將 $n$ 減 1（`n = n - 1`）。
3. 當堆疊清空（`top < 0`）時結束迴圈，主程式呼叫函式並輸出計算結果。

## 程式實作

以下為主要程式碼：

```cpp
#include <iostream>
using namespace std;

int data(int m, int n) {
    int nfu[100000]; 
    int top = -1; 
    top++;
    nfu[top] = m;
    while (top >= 0) {
        int cur_m = nfu[top];
        top--;
        if (cur_m == 0) {
            n = n + 1;
        } 
        else if (n == 0) {
            top++;
            nfu[top] = cur_m - 1; 
            n = 1;
        } 
        else {
            top++;
            nfu[top] = cur_m - 1;
            top++;
            nfu[top] = cur_m;  
            n = n - 1;
        }
    }
    return n;
}

int main() {
    int m, n;
    cout << "請輸入 m 和 n: ";
    cin >> m >> n;
    cout << "計算結果 (非遞迴): " << data(m, n) << endl;
    return 0;
}
```


## 效能分析

1. **時間複雜度：** 阿克曼函數為超越指數等級極速成長的函數。對於較小的 $m$ 值：
   - $m = 0: O(1)$
   - $m = 1: O(n)$
   - $m = 2: O(n)$
   - $m = 3: O(2^n)$
   - 一般性表達式為 $O(A(m, n))$，屬於極度爆炸性成長。
2. **空間複雜度：** $O(\text{Max Stack Depth})$。空間開銷取決於執行過程中自訂堆疊 `nfu` 的最大深度，最大開銷與當次運算所需的堆疊深度成正比。

## 申論及開發報告

### 非遞迴實作原因與遞迴比較探討

依據作業規範與限制，本題要求必須使用非遞迴方式實作阿克曼函數（Ackermann's function）。阿克曼函數為經典的非原始遞迴函數（Non-primitive recursive function），其成長速度極快，在實作上是觀察遞迴與非遞迴差異的優良範例。

#### 1. 記憶體管理與堆疊機制之差別

- **遞迴版本（系統 Call Stack）：**  
  遞迴實作仰賴作業系統分配給程式的隱式呼叫堆疊（Implicit Call Stack）。每次進行函式呼叫時，系統都需要為該層遞迴建立新的 Stack Frame（包含返回位址、區域變數與參數），這會帶來不小的 Function Call Overhead。由於系統 Call Stack 容量通常非常有限（通常只有數 MB），阿克曼函數極深的遞迴層次會迅速導致系統產生 **Stack Overflow** 崩潰。
  
- **非遞迴版本（自訂 Explicit Stack）：**  
  本程式依據作業要求改用非遞迴實作，透過手動宣告顯式堆疊（Explicit Stack，即一維陣列 `nfu`）來管理狀態。自訂堆疊存放於主記憶體的資料區（Data Segment），其可分配空間遠大於系統 Call Stack，使得程式在面對深度運算時能承載更多的狀態堆疊，顯著提升了運算開銷的容忍度。

#### 2. 控制流程與子任務調度比較

- **遞迴版本：**  
  遇到雙重遞迴 $A(m - 1, A(m, n - 1))$ 時，編譯器與系統會自動處理評估順序——先展開內層呼叫，待內層傳回結果後再進行外層呼叫。程式碼寫法簡潔直觀，但底層執行細節被系統封裝。

- **非遞迴版本：**  
  必須手動將遞迴呼叫解構成狀態轉移流程。透過將 $m - 1$ 與 $m$ 依序推入 Stack 中，我們手動精確控制了「先計算內層子問題 $A(m, n-1)$，再將結果回傳給外層 $m-1$」的壓棧與彈棧邏輯，展現了利用基本資料結構模擬複雜控制流的能力。

#### 3. 實作優缺點比較與限制

| 比較項目 | 遞迴版本 (Recursive) | 非遞迴版本 (Non-recursive) |
| :--- | :--- | :--- |
| **作業限制符合度** | 不符合作業規範 | **符合本題作業要求** |
| **程式碼可讀性** | 高（極接近數學公式定義） | 較低（需手動管理 Stack 與迴圈狀態） |
| **記憶體空間來源** | 有限的系統 Call Stack | 較大的主記憶體空間（Data Segment/Heap） |
| **執行效能開銷** | 頻繁函式呼叫，Overhead 較高 | 無函式呼叫開銷，狀態轉移效率較高 |
| **堆疊溢位風險** | 輸入極小（如 $m=3, n=4$）即崩潰 | 空間承受力較高，但受限於固定陣列大小 `nfu[100000]` |

#### 4. 總結

雖然阿克曼函數的數學定義天然適合用遞迴表達，但受限於作業規範與系統記憶體架構，採用非遞迴方式實作能讓程式避免系統 Call Stack 的即時溢位。透過本次實作，不僅達成作業要求，也深入理解了顯式堆疊（Explicit Stack）對複雜邏輯的控制能力與兩者在記憶體層面的根本差異。
