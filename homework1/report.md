## 解題說明

本題要求實作阿克曼函數（Ackermann's function），計算 $A(m, n)$ 之值。為了深入探討演算法機制，本作業分別採用**遞迴（Recursive）**與**非遞迴（Non-recursive）**兩種方式進行實作與比較。

### 解題策略

1. **遞迴版本：**
   - 直接將數學定義轉化為條件判斷式。
   - 透過系統隱式呼叫堆疊（Implicit Call Stack）自動處理雙重遞迴 $A(m - 1, A(m, n - 1))$ 的運算順序。
2. **非遞迴版本：**
   - 使用一維陣列 `nfu` 與指標 `top` 自訂顯式堆疊（Explicit Stack）模擬遞迴過程。
   - 透過 `while (top >= 0)` 迴圈處理狀態轉移：
     - 當 $cur\_m = 0$ 時：代表達到基底條件，將 $n$ 加 1（`n = n + 1`）。
     - 當 $n = 0$ 時：對應 $A(m-1, 1)$，更新堆疊頂端為 $cur\_m - 1$，並設 $n = 1$。
     - 其餘情況：對應 $A(m-1, A(m, n-1))$，依序將外層任務 $cur\_m - 1$ 與內層任務 $cur\_m$ 推入堆疊，並將 $n$ 減 1（`n = n - 1`）。

## 程式實作

以下為包含「遞迴」與「非遞迴」兩版本的完整 C++ 程式碼：
1.遞迴
```cpp
#include <iostream>
using namespace std;
int nfu(int m, int n) {
if (m == 0) {
return n + 1;
}
if (n == 0) {
return nfu(m - 1, 1);
}
return nfu(m - 1, nfu(m, n - 1));
}

int main() {
int m, n;
cout << "輸入 m 和 n: ";
cin >> m >> n;
cout << "結果: " << nfu(m, n) << endl
return 0;
}
```
 2. 非遞迴版本
```cpp
#include <iostream>
using namespace std;
int data(int m, int n) {
    int nfu[100000]; 
    int top = -1; 
    top++;
    nfu[top] = m;
    while (top >= 0) {
    int cur_m = nfu[top];
        top--;
        if (cur_m == 0) {
            n = n + 1;
        } 
        else if (n == 0) {
            top++;
            nfu[top] = cur_m - 1; 
            n = 1;
        } 
        else {
            top++;
            nfu[top] = cur_m - 1;
            top++;
            nfu[top] = cur_m;  
            n = n - 1;
        }
    }
    return n;
}
int main() {
    int m, n;
    cout << "請輸入 m 和 n: ";
    cin >> m >> n;
    cout << "計算結果 (非遞迴): " << data(m, n) << endl;
    return 0;
}
```

## 結論

1. **結果一致性：** 遞迴版與非遞迴版在一般輸入情況下（如 $m \le 3$），輸出的計算結果完全一致，驗證了**兩者演算法邏輯的正確性**。
2. **記憶體容量差異：** 遞迴版本受限於作業系統有限的 **Call Stack 容量**，當 $m \ge 4$ 或 $n$ 稍大時會直接引發 **Stack Overflow** 崩潰；非遞迴版自訂陣列開在 **Data Segment**，能承載更深層的任務堆疊，但當超出 `nfu[100000]` 的邊界時依然需要額外動態擴充。

## 申論及開發報告

### 阿克曼函數：遞迴 vs 非遞迴實作差異探討

為了比較兩種寫法的實作差異，本作業同時開發了遞迴與非遞迴版本。阿克曼函數是個數字爆長極快的超狂函數，拿它來比較兩者的差別真的非常有感！

#### 1. 記憶體管理：系統 Call Stack vs 自訂 Stack

- **遞迴寫法（用系統的 Call Stack）：**  
  如果用一般的遞迴寫，程式每呼叫自己一次，系統就會在 Call Stack 裡面開一塊空間（Stack Frame）來記住現在跑到哪、變數是多少。但系統給的 Call Stack 空間非常小（通常才幾 MB），阿克曼函數又會一口氣鑽超級深，結果數字稍微大一點點，系統堆疊就直接被塞爆，跳出慘絕人寰的 **Stack Overflow** 崩潰。

- **非遞迴寫法（我們自己建的 Stack）：**  
  為了避免系統 Stack 溢位，我們改成用非遞迴，並自己宣告一個陣列 `nfu` 當做 Stack。自己建的 Stack 是放在主記憶體的資料區（Data Segment），空間比系統 Call Stack 大太多了！這樣就算運算鑽得再深，程式也比較能頂得住，不會一下就打回原形。

#### 2. 控制流程：自動配對 vs 手動排隊

- **遞迴寫法：**  
  碰到像 $A(m - 1, A(m, n - 1))$ 這種兩層遞迴時，編譯器跟系統會自動幫你處理好「先算內層、再算外層」的順序。程式碼看起來非常乾淨優雅，跟數學公式長得一模一樣，但底層到底是怎麼轉的你其實看不到。

- **非遞迴寫法：**  
  沒有系統幫忙，我們就得自己手動來。程式裡把 $m - 1$ 跟 $m$ 依序推進 Stack 裡面，其實就是我們手動在指揮：「先拿內層的 $A(m, n-1)$ 出來算，算完結果再丟給外層的 $m-1$」。雖然寫起來比較繁瑣，但能完全掌握整個運算過程。

#### 3. 一張表看懂兩者差別

| 比較項目 | 遞迴版本 (Recursive) | 非遞迴版本 (Non-recursive) |
|:---|:---|:---|
| **程式碼可讀性** | 超好讀（跟數學公式一樣直觀） | 比較繞口（要手動管理 Stack 跟 while 迴圈） |
| **記憶體用哪裡** | 空間超小的系統 Call Stack | 空間大很多的自訂陣列 (Data Segment) |
| **執行效率** | 頻繁進出函式，額外開銷（Function Call Overhead）較大 | 無函式呼叫開銷，狀態轉移比較快 |
| **當機 (Overflow) 風險** | 輸入超小（如 $m=3, n=4$）就直接崩潰 | 空間承受力高很多，但受限於陣列 `nfu[100000]` 的大小 |

#### 4. 總結

雖然阿克曼函數用遞迴寫最直覺，但因為系統記憶體的瓶頸，在實際應用上非遞迴版本具有更好的抗溢位能力。透過同時實作這兩種版本，不僅驗證了結果的精確性，也讓我們更清楚看到程式底層在處理複雜邏輯時，記憶體與堆疊到底是怎麼運作的！
